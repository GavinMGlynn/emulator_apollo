## Appendix F is the binary format, field by field

**The object module the loader reads, byte-exact.** Figure F-3's global
information header:

| Offset | Field | Size |
| --- | --- | --- |
| 0 | Start Address — 2-byte section ID + 4-byte offset | 6 |
| 6 | Name, blank-filled | 32 |
| 38 | Version (compilers set 0) | 4 |
| 42 | Creation Time — "the most significant 4 bytes that `time_$clock` returns" | 4 |
| 46 | Number of Sections | 4 |
| 50 | Pointer to Static Resource Information records | 4 |
| 54 | Number of SRI records | 4 |
| 58 | Pointer to Global Table | 4 |
| 62 | Number of Globals | 4 |
| 66 | **Pointer to Shared Libraries** | 4 |
| 70 | **Number of Shared Libraries** | 4 |

The module header before it carries a pointer to the module information tables,
a pointer to the debug table, and "the value of the length (in bytes) of the
object module". A global table entry is **54 bytes**, and "**global references
must precede global definitions**". A section name is 32 bytes, blank-filled,
unique within the module.

**§F.2, what the loader does, in four lines:**

> - Maps read-only sections to memory.
> - Allocates space for read/write sections.
> - **Resolves references to installed libraries using KGT** (Known Global
>   Table).
> - **Initializes data and relocates address in read/write sections.**

**And the read/write template is the mechanism.** §F.5.6: read-only sections are
"represented by memory image format"; read/write sections are "represented in
**template format**", a series of records —

- **Text record**: section id, memory address, byte count (1 to 512), then the
  bytes.
- **Relocation record**, value `2`: a 2-byte count (1 to 128), then per entry a
  2-byte **offset** ("the location of the 4-byte quantity to relocate ...
  relative to the start of the text record") and a 2-byte **reloc base ID**.
  "The loader performs relocation on 4-byte quantities aligned on even-byte
  addresses." **The base ID may name a section *or a global reference*** — the
  worked example's four entries are `5 Global Reference AGAIN`, `1 Section
  PROCEDURE$`, `2 Section DATA$`, `3 Section DEBUG$`.
- **Repeat record**, value `1`: a 4-byte count, repeating the previous text
  record — how `DATA iarray/20*1000/` becomes six bytes.
- **End record**, value `3`.

> "**The zero section attribute causes the loader to set the contents of the
> section to zero *before processing the templates*.**"

## Which completes an account four documents long

The DS5500 calls through a pointer at `0091709C` that holds zero
(`PROJECT_STATUS.md`). Put end to end:

| Document | Its piece |
| --- | --- |
| `[ASM]` §1.4 | "To allow the callee to locate its own impure data section, **the DOMAIN conventions put the entry point to externally-callable routines in the `DATA$` section**" — so an entry point is a relocatable 4-byte quantity in a writable section, which is why a call is `movea.l d(a5),a0; jsr (a0)` |
| `[DP]` ch. 2 | position-independent code "insert[s] an extra level of indirection for each external procedure", and the loader "fills in" that **transfer vector** from the KGT |
| `[ASM]` §F.5.6 | the loader **zeroes the section first**, then applies text records, then relocations; a relocation entry's base ID can be a **global reference** |
| `[BIND]` §4.4.1 | a section other than `data$` is zeroed per process and the program initialises it on first access |
| `[DP]` ch. 4 | an **unresolved** vector points at a **dynamic link snapper**, not at zero |

**So a zero in that slot means one of three things**, and they are now
distinguishable in principle: the section was zeroed and no text record covered
that offset; a text record covered it and no relocation entry named it; or a
relocation ran and resolved to zero. `OBJDMP`, which §F.3 documents — `$ OBJDMP
input_filename [-options] [outputfile]` — dumps exactly these records for a
given `.bin`, and the DS5500 can run it. **That is the cheapest next measurement
on this question and it needs no new instrument.**

## Also from Appendix F

- **Table F-2, the alignment bits**: `00` 4-byte (long, the default), `01`
  8-byte (quad), `10` reserved, `11` **page boundary (1024 bytes)**. A fifth
  independent statement of the 1,024-byte page. "The pure code region of the
  object module is always mapped page-aligned."
- **The old global field**, `FF` true / `0` false, is the `-MARK` mechanism from
  the loader's side: "If the old global field is `0`, the loader enters the name
  and address of the global in the KGT. If ... `FF`, the loader does not." The
  binder sets it to `FF` when copying definitions forward unless `-MARK` or
  `-ALLMARK` overrides.
- The standard sections are **`PROCEDURE$`** (R/O, concatenated, instruction),
  **`DATA$`** (concatenated, data) and **`DEBUG$`** (R/O, concatenated, data);
  a FORTRAN `COMMON` becomes a named overlay data section.
- A real `OBJDMP` listing appears in full at §F.4 and is the reference for every
  field name above.

## The rest, condensed

*Superseded by the full read above; kept as what the first pass recorded.*

`ASM` is a two-pass assembler; the location counter is "a section and an offset
within the section". Names are 1 to 32 characters of letter, digit, underscore
or dollar sign. Every source file begins with `PROGRAM` (main program) or
`MODULE`. **`DFSECT` takes the section attributes directly** —
`[(overlay,] [readonly,] [instruction,] [zero)]` — so the *zero* attribute is
settable in source, which is the other end of §F.5.6's rule. `PROC`/`DATA`/`SECT`
switch the location counter between sections; `ENTRY` exports a name, `EXTERN`
imports one; `CPU` selects the target processor, and the manual notes a 68020
32-bit displacement form assembling "into an address register indirect (base
displacement) mode with a suppressed index register". Chapter 7 gives the
calling conventions and the stack frame field order "from bottom to top (the
order in which they are pushed)", and a floating-point **TYPE CODE**, "This
16-bit word identifies the type of floating-point processor for which register
information is being saved". Chapter 8 covers the two mathematical libraries and
calling the FPP, which "destroys all register contents except" a named set.
Appendices A-E are error codes, legal mnemonics, and worked examples.

**Nothing in this document changes any code here.** It is a format and a set of
conventions for software this core runs rather than emulates. Its value is that
it makes the DS5500's remaining symptom measurable with a tool the machine
already has.
