**Why it is being walked.** `CLAUDE.md` uses this document as the whole-document
rule's own worked example: it "was grepped and declared silent, then read as page
images and yielded three registers, a whole address map, a fourth memory bank and
a bank-layout correction — from ten pages." It has therefore already triggered
the rule, is cited in 19 files, and **had no coverage record**. It is also the
shortest unwalked hardware document held.

## Method

- **Native resolution is 400 ppi**, `pdfimages -list` confirmed, and the coding
  is **1-bit JBIG2** — the same format whose symbol substitution mangled
  `010005-00`'s superscripts. Assume every exponent and small digit in the text
  layer is suspect; read the page images and check arithmetic.
- The document is an **addendum**: each page says which page of the parent
  handbook it replaces. Record the replacement target, because a reader holding
  the parent will otherwise use the superseded page.

## What the walk yielded

**The addendum is mined, not unmined.** Six of its ten pages are technical, and
five of those six were already derived into `ap_board`, `ap_atmap` and
`ap_boardreg` — in detail, with this document cited, in one case the manual's
polarity sentence quoted verbatim, and in another with the model **ahead** of
the page. `CLAUDE.md`'s worked example describes work that was *done*; what was
missing was the coverage record proving which pages were read. That is what this
file now is.

**Two things this core does not have:**

1. **`F8000000`–`FDFFFFFF` DESKTOP VISUALIZATION SPACE**, 96 MB, zero hits in
   `src/`. Decide whether to place it — reporting unmapped rather than zero, as
   this core does elsewhere — or name it a gap. Reported as ordinary unmapped
   space it is not *wrong*, but it is unnamed, and a trace cannot then say what
   the firmware reached for.
2. **The DS5500 has a SCSI bus** (Figure 1-5, to magtape and cartridge tape) and
   this core models no SCSI at all. Subsystem-sized; a plan item in its own
   right if the DS5500 is to be supported.

**One open item confirmed from the page**: the address translation map is
`017000`–`017FFF`, 4 KB, against `[S3K]` §2.5's 2 KB. The plan item now carries
the warning that the firmware probe at `01002BF6` walks only to `0177FE`, so the
machines may genuinely differ and `AP_ATMAP_ENTRIES` may need to become
per-model rather than simply doubling.

**One blocker verified rather than repeated**: the Table 4-6 item waits on
`007861`, and the Preface pins that to **`007861-A01`**. The bitsavers
`pdf/apollo/` index was fetched directly and lists no `007861` file at all; a web
search finds the handbook catalogued in two forms but no scan. Reference, web and
this addendum are exhausted.

**A trap worth carrying**: Figures 4-9 and 4-10 are the **same register drawn
twice**, in two styles with identical legends. An addendum printing one register
two ways is where a careless reader finds two — the same shape of mistake as
`002398-04` printing one ST3 table in both chapter 8 and chapter 12.
