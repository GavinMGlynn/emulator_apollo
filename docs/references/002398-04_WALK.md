## How to read this record

Every page range gets a row, including the ones that yield nothing: a section
recorded as *no emulator content* is a finished section, and that is what makes
a **walked** document distinguishable from a **sampled** one later. Pages are
read as **images**, never as a text layer.

Status values: `derived` (everything in it is in code or in a named gap),
`confirms` (agrees with code already, nothing to change), `none` (no emulator
content), `GAP` (something is missing from code and is named).

**Debts are recorded in the Resume block, not left implicit.** The `008778-03`
walk incurred two — both from reading a later page out of order to establish a
section's extent — and both were paid, *because they were written down*.

## The reading order, and why it is not front-to-back

`008778-03` was walked in page order because every chapter described the machine
this core models. This handbook does not: **chapters 7 through 11 are other
machine families** — DN300/320/330, DN400/420/600, DN460/660/DSP160, DN5xx,
DSP80/80A/90 — and only **chapter 12 is the DN3000**, which is the family
`src/core/model/` is built around.

So this walk takes **chapter 12 first**, then chapters 1–6 (which are
machine-independent: AEGIS structures, the file system, error codes, debugging,
peripheral I/O), then 7–11 and the appendices. Every page is still read; only
the order changes, and it changes so that the pages most likely to hold a
missing fact are reached first.

That decision is recorded here rather than left to look like an omission, and
the Resume block above is the authority on what has actually been covered.
