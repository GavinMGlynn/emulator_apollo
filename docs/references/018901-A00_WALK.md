## §1.4.1 corrected a field and confirmed four others

> "SR10.4 provides support for the new Domain Series (DS) 5500, which is an
> **MC68040-based CPU board upgrade** to the Domain Series 3500, 3550, and 4500
> personal workstations.
>
> All existing graphics, networks, mass storage, and backup devices presently
> available on the DN3500, DN3550 and DN4500 workstations are supported. All
> memory modules shipped with the DN3500, DN3550 and DN4500 workstations are
> also supported. In addition, a **new 16-MB memory module has been added which
> gives the DN5500 a total memory capacity of 64 MB**.
>
> Because the MC68040 combines the MC68030 and MC68882 chip set into one package
> and provides greater performance, the **Floating-Point Accelerator Board**
> presently available on the DN3500, DN3550 and DN4500 **is not supported** on
> the DN5500.
>
> **The PC AT bus and onboard I/O are retained on the DN5500.** To optimize
> performance, a **new memory controller and bus interface** have been designed.
> **A new I/O protection mechanism has been designed to support the 4-KB page
> I/O mapping of the MC68040.** The new CPU board uses the **25 MHz** version of
> the MC68040."

**The correction**: `ap_model.c` gave the DN5500 a 32 MB ceiling citing `[CFG]`,
the *HP-Apollo Products Configuration Guide* of **December 1989** and its July
1990 quick reference — **both two years older than the machine**. It is 64 MB.
`model_suite` then required the DSP5500 row to follow, which is the suite
catching the second half rather than the author remembering it.

**The confirmations**: the 25 MHz clock, the on-chip FPU with no accelerator
board, and the retained AT bus and onboard I/O were all already in the row from
other sources.

**And one sentence names something this project found the hard way.** "A new I/O
protection mechanism has been designed to support the 4-KB page I/O mapping of
the MC68040" is `board/ap_ioprot.*`, which exists because a DS5500 PROM clears
four long words at `07000000` before it has a stack and the machine died 137
instructions in without it. `019411-A00` Table 2-5 named the region; nothing
said what it was *for*. **The empirical placement and the documented purpose
agree and neither was derived from the other.**

*It also settles the naming*: the document uses "Domain Series (DS) 5500" and
"DN5500" in adjacent sentences for the same machine, which is why both appear
across this project's own records.
