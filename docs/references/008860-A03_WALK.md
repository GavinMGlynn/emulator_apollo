## What it is

295 pages, Hewlett-Packard/Apollo, March 1992 — the SR10.4 installation manual,
and therefore the manual for the exact procedure this project has been executing
by hand since Phase 4. Three parts: **Part 1** installation tasks (chapters 1–5),
**Part 2** advanced tasks (6–9), **Part 3** reference (10–12), then a glossary
and index.

It was **cited before it was read** — the DN5500 item quotes its Table 1-1 for
the SAU numbers — which is the shape `read-the-whole-document` names.

## Calibration: the OCR layer drops what this project needs most

Scanned at **400 dpi bitonal**, JBIG2, with an Acrobat 9 Paper Capture text
layer. `pdfimages -list` first, per `002398-04_WALK.md` — 200 dpi rendering is
comfortably legible, so nothing here needs the 600 dpi that
`render-handwriting-at-600dpi` calls for.

**The text layer is good for prose and cannot be trusted for identifiers**, and
that was measured rather than assumed — page images compared against the
extraction, page for page, on every page listed below:

- **A value is dropped outright.** p. 1-13 (physical 46) reads "The
  cartridge-tape boot volume is labeled **`crtg_std_sfw_boot_1`**. Make sure the
  boot tape is write-disabled." The extraction gives "The cartridge-tape boot
  volume is labeled                         Make sure" — the label is **not in
  the text layer at all**, in either `-layout` or raw mode. A grep for it over
  this document comes back empty on a document that states it.
- **Identifiers are corrupted.** p. 1-20 has `miDst` twice for **`minst`**;
  elsewhere `CRTG_STD_SFW_l` for `CRTG_STD_SFW_1`, `tum` for `turn`,
  `instail` for `install`, `Ilserver` for `//server`.
- **Prose is faithful.** Checked word for word on pp. I-10, 1-2, 1-13, 1-18,
  1-19 and 1-20 against the images; no substantive difference.

*Which matters here specifically.* `crtg_std_sfw_boot_1` is the **boot**
cartridge and `CRTG_STD_SFW_1` is the first **distribution** cartridge — two
different tapes, and this project holds both, as
`019593-001.CRTG_STD_SFW_BOOT_1-REV.A.ct` and `019594-001.CRTG_STD_SFW_1.ct`.
The manual confirms the identification, and the page that names the boot one is
exactly the page whose text layer has lost it.

### What those pages already changed

- **The `swap PATH` console-script verb exists because of p. 1-20.** An install
  asks for one distribution cartridge at a time, so a frontend with one drive
  and no way to change its media cannot answer. `src/core/board/ap_tape.c`'s
  `ap_tape_eject` and the verb are in `PROJECT_STATUS.md`.
- **It is the third independent witness that a restore is not an install.**
  Step 3 is `invol` plus a boot from the cartridge; **Step 4** is what installs.
  `sr10-3-install-route` said the same from a run, and the volumes on disk say
  it a third way — `dn3500-sr10.3-osclean.awd`, restore-only, has `55` fill
  where `SYSBOOT ` goes.
