item read "Phase 2b and Phase 7 parts ... **Deferred until those processors are

`src/core/model/ap_model.c` gives **three** rows `.cpu = AP_CPU_M68020` (DN3000,

the model table is not a future part.

## The citation audit, which is where this walk starts

The rule the batch item sets — "do the citation audit first, per document; it is
one grep" — and its answer here is the opposite of `[030]`'s. There, §7-§9 and
§11 held 88 of 90 citations and were *verification*, which halved the job.

Here: `src/` and `tests/` mention the 68020 **473 times**, and only **six** of
those cite this manual with a place — §1, §7.1.1, §9.2.1 and Appendix D. The
other 467 are prose about the part, written from `[030]`'s and `[PRM]`'s
descriptions of what the 68020 does differently. **So there is almost no
verification to lean on and the 452 pages are new reading.** Recorded because it
is the estimate the walk is planned against, not an aside.

| 148-151 | **§7 ON-CHIP CACHE MEMORY**, 7.1 Design and Operation, 7.1.1 Organization, 7.1.2 Cache Control, 7.1.2.1-7.1.2.5 CACR and its four bits, 7.2 Cache Address Register, 7.3 Cache Disable Input, 7.4 Cache Initialization | `confirms` **two model-table values — and finds a register this core would get wrong for three of its own models** | **Confirms** `ap_model.h` exactly: "a direct-mapped cache of **64 long word entries**" is its 256 bytes, and the NOTE "**Data accesses are not cached, regardless of their associated address space**" is its zero data cache. **Three facts the table does not carry**: the tag is the upper 24 address bits **plus `FC2`**, so one address in supervisor and user space occupies two entries; the index is `A2-A7` and `A1` selects the word within the entry; and "the processor always prefetches instructions externally with **long word, aligned bus cycles**, [so] both words of the entry will be updated, regardless of which word caused the miss". **And the register: the 68020's CACR is four bits** — `C` clear cache (3), `CE` clear entry (2), `F` freeze (1), `E` enable (0), with "the unused bits (including bits [31:8] which are not shown) ... always read as zeros". The 68030's has eleven. `ap_machine` builds an `ap_m68030_cpu_t` unconditionally, so a DN3000 or DN4000 in this core gets a **68030** control register — the same gap the model table's `.mmu` item names, now with a second register behind it. Also: `E` "is automatically cleared whenever the processor is reset"; `CE` uses CAAR's index bits 2-7, invalidates "regardless of whether or not it provides a hit", and is "independent of the state of the E or F bits, or the external Cache Disable (`CDIS`) pin"; `C` and `CE` both "always read as zero"; CAAR is 31-8 Cache Function Address, 7-2 Index, and "the MC68020 only uses this register for the clear entry (CE) function"; `CDIS` is synchronised, takes effect "on the first cache access after" recognition, and disables "independent of the enable bit"; and §7.4's reset clears every valid bit **and** the `E` and `F` bits |
