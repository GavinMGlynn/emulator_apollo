## STATUS: 5 of 722. **Barely started.** Do not read this file as a finished walk.

Opened 2026-08-21.

**Why it is being walked at all.** It was consulted once, for one question —
which DUART pin carries DCD — and the SIO chapter answered a *different* and
better question in four sentences this core did not have. `CLAUDE.md`'s rule
then applies with no discretion: a document that yields one unimplemented fact
is a document to be derived in full, not queried again.

**What it is.** The *software* interface to Domain/OS, not a hardware manual.
Most of its 722 pages are Pascal/C bindings for operating-system calls that an
emulator core never sees. That is not a reason to skip it — `019411-A00` was
declared silent and yielded three registers, an address map and a memory bank —
but it does mean the yield per page is expected to be low outside the chapters
that touch devices. Those are worth finding first.

## Method

- **The text layer is not usable for facts.** It is OCR of a scan and it
  mangles exactly what matters: `DCD` renders as **`DOD`**, `Check` as
  **`Oheck`**, `IOS` as **`lOS`**, `CTRL/Z` as **`OTRLjZ`**. Every `C` in a
  small-caps identifier is a candidate `O`. Use extraction to *locate* pages,
  read the **page images** for anything that is a fact.
- `pdftoppm -r 150` is enough for this document's body text.

## What the read pages have already settled

The SIO options predict the exact register traffic Phase A measured on a booted
machine — one `OPR` bit set at open (`DTR`, default on), the input port read to
inquire `DCD`, one `OPR` bit cleared, and **no** `IPCR` read at all because
`DCD_ENABLE` defaults off and so change-of-state is never armed. The manual and
the machine agree without either having been fitted to the other. Detail in
`PROJECT_STATUS.md`, *Domain/OS reaches a `login:` prompt*.
